# Vitality Chews store

Static storefront + Cloudflare Worker for vitalitychews.com. Replaces the WordPress/WooCommerce site.

- **Pages:** generated by `scripts/build.mjs` from `site/data/*.json` and `site/content/**/*.md` into `dist/`.
- **Checkout:** Stripe Checkout (hosted). Prices come from `site/data/products.json` on the server, never from the browser.
- **Orders:** saved to D1 (`vitality-chews-orders`) by the Stripe webhook. The owner gets an email for each new order and each refund.
- **Refunds:** a full refund marks the order `cancelled` (ShipStation picks that up). A partial refund leaves the order alone so it still ships.
- **Fulfillment:** Rocktomic only imports from WooCommerce, so each paid order is copied into the WordPress/WooCommerce store (`src/woo.js`, REST API key in `WC_CONSUMER_KEY` / `WC_CONSUMER_SECRET`). Rocktomic's ShipStation pulls it from there; a 5-minute cron copies tracking back and retries failed copies. Cancelling or fully refunding here cancels the WooCommerce copy. (`/api/shipstation` is a ShipStation Custom Store endpoint that Rocktomic declined to use; it is kept but unused.)

## Customer email and admin portal
Mail for vitalitychews.com runs on Cloudflare (no Google Workspace):
- **Receiving:** Email Routing's catch-all sends every address to this Worker (`email()` in `src/mail.js`). Messages are stored in D1 (`threads`, `messages`), attachments in R2 (`vitality-chews-mail`). The contact form at `/contact/` lands in the same inbox.
- **Notices:** the owner (`ORDER_NOTIFY_TO`) gets a note from `inbox@` with a button to the admin. Reply-To is a signed `reply+<id>-<sig>@` address, so replying from your own inbox sends **only the new text** to the customer, from `hello@`. Quotes and anything below a `--` signature line are removed. Replies are accepted only from `ORDER_NOTIFY_TO` with a passing DKIM/DMARC result. Set `INBOX_NOTIFY_BODY` to `"false"` to leave the customer's text out of notices.
- **Admin:** `/admin` (inbox, replies, new email, orders). Sign-in is a one-time link emailed to `ORDER_NOTIFY_TO`. `ADMIN_BASE_URL` sets the links in emails; change it to `https://vitalitychews.com` when the domain points here.
- Mail to `inbox@` and `orders@` bounces. Auto-replies and bulk mail are stored without a notice.

## Edit content
- Products, prices, SEO titles, FAQs: `site/data/products.json`
- Site settings (free-shipping threshold, flat rate, email): `site/data/site.json`
- Pages and policies: `site/content/pages/*.md`
- Guides: `site/content/learn/*.md` (front matter `product:` links a guide to a product)

## One-time setup
1. `npx wrangler d1 create vitality-chews-orders` and put the id in `wrangler.jsonc`, then `npm run db:migrate`.
2. Secrets: `npx wrangler secret put STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `SHIPSTATION_USER`, `SHIPSTATION_PASS`, `ORDER_NOTIFY_TO` (where order alerts go; must be a verified Email Routing destination address).
   Order alerts send from `orders@vitalitychews.com`, so onboard vitalitychews.com in Cloudflare **Email Service > Email Sending** once. That adds sending records only; it does not touch the Google Workspace MX records.
3. Stripe webhook → `https://vitalitychews.com/api/stripe-webhook`, events: `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `charge.refunded`.
4. Give Rocktomic the ShipStation Custom Store details:
   - URL: `https://vitalitychews.com/api/shipstation`
   - Username / password: the `SHIPSTATION_USER` / `SHIPSTATION_PASS` values
   - Status mapping: `paid` = Awaiting Shipment, `shipped` = Shipped, `cancelled` = Cancelled
5. Point the domain at the Worker with a **Route** (`vitalitychews.com/*` and `www.vitalitychews.com/*`), not a Custom Domain, keeping the existing proxied DNS record for the WordPress server. Then set `WP_PASSTHROUGH` to `"true"` and `ADMIN_BASE_URL` to `https://vitalitychews.com`. WordPress admin, the WooCommerce API and the ShipStation plugin keep working at the same address, so Rocktomic's connection does not change.

## Images
All images in `site/static/img` came from the WordPress media library and were resized and converted to WebP:
- `products/<sku>-600.webp` / `-1200.webp`: bottle renders (transparent). `products/<sku>.jpg`: the same render on white, used by Stripe Checkout, ShipStation and social previews.
- `products/<sku>-facts*.webp`: Supplement Facts panels. `products/<sku>-coa.jpg`: lab certificates of analysis.
- `photos/`: lifestyle photos (`-900` and `-1800` widths). `badges/`: certification seals. `lineup-*.webp`: the five bottles together.
- Each product's colors (`theme`) live in `products.json`.

## Local
`npm install && npm run dev` (create `.dev.vars` with the secrets above).
